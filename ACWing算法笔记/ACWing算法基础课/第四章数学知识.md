## 1、质数

### 是什么：

质数指的是所有大于等于2的自然数中只能被1和本身整除的数



### 怎么办：

#### 如何判定质数呢？

对于判定整数n是否是质数除了用定义从2一直尝试到n-1看看能否被整除以外（该算法的时间复杂度为O(n)），还可以有其他办法吗？

当然有，首先我们得知道一个定理，那就是如果n能被d整除那么n一定能被(n/d)整除，即d和(n/d)是成对出现而且一大一小的（二者的乘积就是n），那么这二者什么时候相等呢？即d=(n/d)得到d=sqrt(n)，知道了这个道理我们再看上面的过程是不是觉得有些冗余，我们判定一个数n能否被整除为什么非要从2开始一直遍历到n-1遍历完所有比它小的数呢？如果我们遍历完了从2开始一直到sqrt(n)都没有发现n的约数（即n能被整除的数）那么对于sqrt(n)到n的这一半肯定也不存在它的约数。

综上，我们就可以将遍历的上限限定到sqrt(n)，时间复杂度缩短到O(sqrt(n))



### （866）试除法判定质数

![1690079025239](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690079025239.png)

解题思路：

别忘了质数的前提是要大于等于2，同时注意这里i<=n/i的这种写法

```Java
import java.util.*;
public class Main{
    static boolean isPrime(int n){
        if(n<2){//别忘了质数要大于等于2的前提
            return false;
        }
        for(int i=2;i<=n/i;i++){
            /*
            注意这里的i<=n/i这种写法，
            这里不要写成i<=sqrt(n)的形式，因为这样每次都要计算一次sqrt(n)挺麻烦的，
            也不要写成i*i<=n的形式，因为这样i*i会有溢出int型范围的风险
            */
            if(n%i==0){
                return false;
            }
        }
        return true;
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n;
        n=sc.nextInt();
        for(int i=1;i<=n;i++){
            int a=sc.nextInt();
            if(isPrime(a)){
                System.out.println("Yes");
            }else{
                System.out.println("No");
            }
        }
    }
}
```





### （867）分解质因数

![1690080786319](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690080786319.png)

解题思路：

#### 什么叫做分解质因数？

就是将一个数分解成几个质数的乘积的形式

#### 如何分解质因数呢？

常规想法就是首先我们将所有的质数枚举出来，然后从中找可以相乘得到该数的几个质数。但是该方法复杂。

有没有更好的办法呢？当然有，用试除法分解质因数，原理和上述判定质数差不多，我们遍历从2到n-1的所有数看看n能否被当前遍历到的数整除，如果能的话我们就让n除以当前遍历到的数i，如果(n/i)依然能被i整除的话我们就让(n/i)继续除以i直到无法整除为止，接着继续遍历i+1，i+2,,,一直遍历到n-1重复上述过程，这样就能得到分解质因数的结果了。

对于上述过程有疑问吗？有，那就是首先上述过程遍历的是所有的数而不是所有的质数，那么这个过程中就会出现合数的情况，这样不会有问题吗？

不会有问题，假设数i是合数，在遍历到i之前我们会先遍历2~(i-1)，把这些都遍历完了才会去遍历i，而且假如n能被(i-1)整除的话那么n会一直除以(i-1)直到无法整除为止，所以当遍历到i的时候一定是2~(i-1)已经没法再遍历的时候，因为i是合数所以它的因子一定存在于2~(i-1)之间，而这些数已经没法再整除n了所以i也没法再整除n了。综上，我们遍历所有的数的这个过程没有问题。

那么对于上述过程还有没有可以改进的地方呢？

有，和试除法判定质数的过程一样，我们可以缩短遍历过程的上限为sqrt(n)，这样缩短时间复杂度为O(sqrt(n))，注意当设定遍历的上限为sqrt(n)的话得注意一个问题，那就是该数可能存在一个大于sqrt(n)的质因数（注意这样的质因数有的话仅有一个），那么当遍历的上限规定为sqrt(n)之后我们没法再遍历到该大于sqrt(n)的质因数了。所以这时候我们得再检查一下此时的n，如果经过2~(sqrt(n))的遍历以后数n不是1的话那么该数就是大于sqrt(n)的质因数了。

```Java
import java.util.*;
public class Main{
    static void divide(int n){
        for(int i=2;i<=n/i;i++){//为什么这里可以遍历所有的数而不是遍历所有的质数，上面已经说过了。
            if(n%i==0){
                int s=0;
                while(n%i==0){
                    n/=i;
                    s++;
                }
                System.out.println(i+" "+s);
            }
        }
        if(n>1){
    		//经过2~sqrt(n)的遍历以后如果n不是1的话那么此时的n就是大于sqrt(n)的质因数
            System.out.println(n+" "+1);
        }
        System.out.println();
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        for(int i=1;i<=n;i++){
            int a=sc.nextInt();
            divide(a);
        }
    }
}
```





### （868）筛质数

![1690167135280](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690167135280.png)

解题思路：

#### 什么叫做筛质数呢？

就是从1~n中提取出所有的质数

#### 如何筛质数呢？

##### （1）解法一：暴力做法

我们对于1~n的每个数都运用上述的试除法isPrime()判定一次看看它是否是质数，这种做法可行但是每次都要调用函数isPrime()实在太麻烦了

##### （2）解法二：暴力筛法

我们从2开始遍历每个数，当遍历到i的时候我们就将i的倍数排除出质数的行列（它既然是i的倍数了那么一定不会是质数），就这样直到遍历到n-1，该算法的时间复杂度为O(nlogn)，**分析该算法的时间复杂度为什么是O(nlogn)？当遍历到2的时候将1~n中所有2的倍数筛掉这个过程会进行n/2次（因为1~n中所有2的倍数的数共有n/2个），当遍历到3的时候将1~n中所有3的倍数筛掉这个过程会进行n/3次，，，，所以最后的操作数是（n+n/2+n/3+n/4+...+1）=n*(1+1/2+1/3+1/4+...+1/n)=n * lnn<nlogn(注意这里的logn指的是以2为底n的对数)**，上述过程图示如下，**但是一般不用这种做法，原因下面会介绍**

![1690170891325](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690170891325.png)

```Java
//对应解法二的代码：
import java.util.*;
public class Main{
    static int N=1000010,n,cnt;
    static int[] primes=new int[N];//用来记录所有质数的数组
    static boolean[] st=new boolean[N];//用来记录1~n中每个数是否是质数
    static int getPrimes(int n){
        for(int i=2;i<=n;i++){
            if(!st[i]){//如果i是质数的话
                primes[cnt++]=i;
            }
            for(int j=i+i;j<=n;j+=i){
                st[j]=true;
            }
        }
        return cnt;
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        n=sc.nextInt();
        System.out.println(getPrimes(n));
    }
}
```



##### （3）解法三：朴素筛法

观察上述过程看看是否有可以改进的地方，发现当遍历到2的时候我们会筛掉所有2的倍数，当后续遍历到4的时候筛掉所有4的倍数但是4的倍数天然就是2的倍数，所以就没必要再去筛掉4的倍数了，综上对于所有的合数我们都没必要再去筛掉它们的倍数了（因为既然它是合数的话那么它的前面一定存在它的质因子，只要我们筛掉所有质数的倍数那么所有合数的倍数天然就被筛掉了），该算法的时间复杂度取决于1~n中有多少个质数，结论：该算法的时间复杂度为O(nloglogn)（对，没错，这里就是 n * loglogn）

```Java
//对应解法三的代码：该算法只是将所有质数的倍数筛掉
import java.util.*;
public class Main{
    static int N=1000010,n,cnt;
    static int[] primes=new int[N];//用来记录所有质数的数组
    static boolean[] st=new boolean[N];//用来记录1~n中每个数是否是质数
    static int getPrimes(int n){
        for(int i=2;i<=n;i++){
            if(!st[i]){//如果i是质数的话
                primes[cnt++]=i;
                for(int j=i+i;j<=n;j+=i){
                    /*
                    这一步筛掉所有倍数的过程嵌套在外层for循环里面表示仅仅筛掉所有质数的倍数
                    */
                	st[j]=true;//记录数j不是质数
            	}
            }
        }
        return cnt;
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        n=sc.nextInt();
        System.out.println(getPrimes(n));
    }
}
```



##### （4）解法四：线性筛法

针对上述的朴素筛法效果已经很好了，但是上述算法还是有些冗余，比如6这个数会被2筛取一遍然后又会被3筛取一遍这是浪费时间的，为了避免这种情况我们让每个合数只被它的最小质因子筛取一遍

如何做到每个合数只被它的最小质因子筛取一遍，后续不再被筛取呢？

那就是在遍历所有数的同时额外用一个数组记录当前遍历到的所有的质数，然后将此质数的倍数（此质数的倍数一定是合数）排除，但是这里一定得保证该质数是该合数的最小质因子，如何保证该质数是该合数的最小质因子呢？具体见下代码：

```Java
static int getPrimes(int n){
        for(int i=2;i<=n;i++){
            if(!st[i]){//如果i是质数的话
                primes[cnt++]=i;
            }
            //这里的目的是确保每个合数只被它的最小质因子筛取一遍
            for(int j=0;primes[j]<=n/i;j++){
                st[primes[j]*i]=true;//将质数的i倍标记为合数
                if(i%primes[j]==0){
                    break;
                }
                /*
                这里primes[j]一定是primes[j]*i的质因子，至于是不是最小质因子得讨论
                （1）当i%primes[j]!=0时
                因为primes[j]是从小到大开始遍历的，而i%primes[j]!=0，所以说明此时的primes[j]
                一定小于i的最小质因子，所以primes[j]一定是primes[j]*i的最小质因子
                （2）当i%primes[j]==0时
                因为primes[j]是从小到大开始遍历的，而i%primes[j]==0，所以说明此时的primes[j]
                一定是i的最小质因子，所以primes[j]一定是primes[j]*i的最小质因子
                
                到这里都没有问题，那为什么当i%primes[j]==0时要用break跳出循环呢？
                这里假设我们不退出循环的话会发生什么？继续用primes[j+1]来筛取合数，下一个合数就是
                primes[j+1]*i，但是这时候的primes[j+1]是primes[j+1]*i的最小质因子吗？
                已经不是了，因为这时候的i%primes[j]==0，说明此时对于primes[j+1]*i来说有更小的
                质因子primes[j]，所以primes[j+1]*i会被primes[j]筛取而前面也说了我们要确保每个
                合数只被最小质因子筛取一遍，所以这里当i%primes[j]==0时要用break跳出循环
                */
            }
        }
        return cnt;
    }
```



```Java
//对应解法四的代码：
import java.util.*;
public class Main{
    static int N=1000010,n,cnt;
    static int[] primes=new int[N];//用来记录所有质数的数组
    static boolean[] st=new boolean[N];//用来记录1~n中每个数是否是质数
    static int getPrimes(int n){
        for(int i=2;i<=n;i++){
            if(!st[i]){//如果i是质数的话
                primes[cnt++]=i;
            }
            for(int j=0;primes[j]<=n/i;j++){
                st[primes[j]*i]=true;
                if(i%primes[j]==0){
                    break;
                }
            }
        }
        return cnt;
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        n=sc.nextInt();
        System.out.println(getPrimes(n));
    }
}
```





## 2、约数

### 是什么：

给定一个正整数a如果它能被正整数b整除的话那么我们就说b是a的约数



### 怎么办：

#### 约数定理（约数个数定理）

是用来判定一个数到底有多少个约数的定理。该定理表述如下：

设n是一个正整数，将n进行质因数分解：n = p1^a1 * p2^a2 * ... * pk^ak，其中p1、p2、...、pk为不同的质数，a1、a2、...、ak为正整数指数。那么n的约数个数可以表示为：(a1 + 1) * (a2 + 1) * ... * (ak + 1)。换句话说，将n进行质因数分解后，约数个数等于每个质因数的指数加1后的乘积。

这是为什么呢？

首先我们不要看那么复杂的情况先拿一个数来举例子，**当n=p1^a1（p1为质数）的时候此时数n的约数有多少个呢？答案是：1，p1，p1^2，p1^3，，，p1^a1总共有a1+1个（注意这里要求的是n的约数，所以只要满足能整除n就可以了）**；再来看复杂的情况，当n=p1^a1 * p2^a2 * ... * pk^ak时（**其中p1、p2、...、pk为不同的质数**），此时的n有多少个约数呢（**约数就是满足能把n整除就可以了**）？我们一项一项的看，首先对于p1^a1这一项来说它有多少个约数呢？答案是a1+1个约数（见上述分析），对于p2^a2这一项来说它有多少个约数呢？答案是a2+1个约数，，，，对于pk^ak这一项来说它有多少个约数呢？答案是ak+1个约数。那么综合这么多项一起看有多少个约数呢？答案就是（a1+1）*（a2+1） *... *（ak+1），因为当你在第一项p1^a1中取它的约数的时候你可以在（a1+1）个约数中随便取一个，当你在第二项p2^a2中取它的约数的时候你可以在（a2+1）个约数中随便取一个，，，，当你在第k项pk^ak中取它的约数的时候你可以在（ak+1）个约数中随便取一个。这些约数的乘积依然是n的约数（**注意这里求的是n的约数，所以只要满足这些乘积能将n整除就可以了不是说这些数的乘积必须得是n**）



### （869）试除法求约数

![1690340302981](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690340302981.png)

解题思路：

和上述试除法求质数差不多，我们只需要遍历到sqrt(n)就可以了，没必要完全遍历到n

```Java
import java.util.*;
public class Main{
    static void divide(int n){
        ArrayList<Integer> list=new ArrayList<>();
        for(int i=1;i<=n/i;i++){
            if(n%i==0){
                list.add(i);
                if(n/i!=i){
                    list.add(n/i);
                }
            }
        }
        Collections.sort(list);
        for(int i:list){
            System.out.print(i+" ");
        }
        System.out.println();
    }
```

### （870）约数个数

![1690463862710](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690463862710.png)

解题思路：

#### 怎么办：

约数定理的使用。这里值得注意的事情有以下一点：

##### 这里是先后依次输入n个整数ai然后求这些数的乘积的约数个数，那么我们需要先将这些数的乘积算出来然后再去分解质因数吗？

其实不用的，这里每次输入一个ai以后我们就对ai分解质因数进行统计它的底数和指数是多少，最后的结果是一样的

##### 为什么计算结果对1e9+7取模？

因为这里的计算结果可能会很大，超出int型表示范围，所以我们在int型范围内弄一个很大的质数然后让计算结果对其取模这样避免数据溢出，另外有一点需要注意的是这里的1e9+7这是浮点数的表示方法，我们得将它转换成int类型，方法就是强制类型转换。

```Java
import java.util.*;
public class Main{
    static int mod=(int)1e9+7;//最后结果对该数取余
    static HashMap<Integer,Integer> map=new HashMap<>();
    static void divide(int n){
        for(int i=2;i<=n/i;i++){
            while(n%i==0){
                n/=i;
                if(map.containsKey(i)){
                    map.put(i,map.get(i)+1);
                }else{
                    map.put(i,1);
                }
            }
        }
        if(n>1){
            if(map.containsKey(n)){
                    map.put(n,map.get(n)+1);
            }else{
                map.put(n,1);
            }
        }
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        for(int i=1;i<=n;i++){
            int a=sc.nextInt();
            divide(a);
        }
        long res=1;
        for(int v:map.values()){//注意哈希表中得到value值集合的方法
            res=res*(v+1)%mod;
        }
        System.out.println(res);
    }
}
```





### （871）约数之和

![1690463907279](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690463907279.png)

解题思路：

#### 怎么办：

##### 约数之和该如何求解呢？

要求解一个正整数的约数之和，可以通过质因数分解的方法来实现。首先，将该正整数进行质因数分解，然后根据分解后的质因数及其指数计算约数之和。

假设要求解的正整数为n，并且它的质因数分解为：n = p1^a1 * p2^a2 * ... * pk^ak，其中p1、p2、...、pk为不同的质数，a1、a2、...、ak为正整数指数。

那么n的约数之和可以表示为：(1 + p1 + p1^2 + ... + p1^a1) * (1 + p2 + p2^2 + ... + p2^a2) * ... * (1 + pk + pk^2 + ... + pk^ak)

##### 对于等比数列求和1 + p1 + p1^2 + ... + p1^a1该如何求解呢？

利用循环，首先令res=1，然后每次循环令res=res*p1+1，这样经过a1次循环后就得到1 + p1 + p1^2 + ... + p1^a1的值。

##### 对于两个等比数列各自求和的乘积比如：(1 + p1 + p1^2 + ... + p1^a1) * (1 + p2 + p2^2 + ... + p2^a2) 又该如何求解呢？

这里千万得注意，两个等比数列的求和得各自分开计算，千万不能混合在一起，比如说我们首先算得1 + p1 + p1^2 + ... + p1^a1这个等比数列求和的结果是c，我们不能接着拿c去进行第二个等比数列求和的计算：令c=c*p2+1这样经过a2次循环以后是得不到 c * （1 + p2 + p2^2 + ... + p2^a2）的结果的

```Java
import java.util.*;
public class Main{
    static int mod=(int)1e9+7;
    static HashMap<Integer,Integer> map=new HashMap<>();
    static void divide(int n){
        for(int i=2;i<=n/i;i++){
```

解题思路：

#### 怎么办：

##### 如何求最大公约数？辗转相除法（欧几里得算法）

这里首先得知道一个定理，那就是（a，b）的最大公约数一定和（b，a%b）的最大公约数相同。为什么？

首先我们得将a%b换种表述方式：a%b=a-kb(其中k=a/b)，所以（a，b）的公约数一定是（b，a-kb）的公约数(注意这里不仅仅是最大公约数而是公约数)，即我们可以由左边推到右边；接下来我们看能否由右边推到左边，已知一个数是（b，a-kb）的公约数，那么说明这个数能将b整除而且能将a-kb整除所以这个数肯定能将a-kb+kb整除，这里对于（b，a-kb）的任意一个公约数都成立，也就是说（b，a-kb）的公约数一定是（a，b）的公约数，也就是说能从右边推到左边，所以（a，b）的公约数一定和（b，a%b）的公约数相同，既然所有的公约数都相同那么二者的最大公约数也肯定相同。

所以我们可以将求（a，b）的最大公约数不断迭代为求（b，a%b）的最大公约数，这样逐步将（a，b）两个数缩小直到最后得出结果。

## 3、欧拉函数

### 是什么：

对于给定的正整数 n，欧拉函数 φ(n) 表示小于 n 且与 n 互质（公共因子只有1，1与所有数都互质）的正整数的个数。换句话说，φ(n) 统计了在 1 到 n 之间，与 n 互质的正整数的个数。

例如：

φ(1) = 1，因为在 1 之前没有比 1 小的正整数，且 1 和 1 本身互质。

φ(6) = 2，因为小于 6 且与 6 互质的正整数是 1 和 5。

φ(10) = 4，因为小于 10 且与 10 互质的正整数是 1、3、7 和 9。

欧拉函数的计算方法是通过对 n 进行质因数分解，并利用欧拉函数的性质来计算的。对于一个正整数 n，如果它的素因子分解为 p1^a1 * p2^a2 * ... * pk^ak，其中 pi 是不同的素数，那么欧拉函数可以通过以下公式计算：

φ(n) = n * (1 - 1/p1) * (1 - 1/p2) * ... * (1 - 1/pk)



### notes：约数和互质是两个概念

a是b的约数意思是说a能够整除b，a与b互质意思是说a与b的公共因子只有1



### 为什么：

#### 欧拉函数为什么成立？

我们想要正面求解在1~N中找到与N互质的数太难了（得一个数一个数去试），所以这里我们侧面求解：先找到1~N中所有与N不互质的数（不互质的数就好求了，找到N的所有质因子，然后质因子的倍数都是与N不互质的），然后再排除掉这些数那么剩下的数就是和N互质的数了。

基于这个思想我们往下做，假设对N进行质因数分解的结果如下：

N=p1^a1 * p2^a2 ... * pk^ak（其中p1，p2，，，pk为质数），则1~N中与N不互质的数有哪些呢？

有：（p1，p1 * 2，，，p1 * k1）(其中k1=N/p1)，（p2，p2 * 2，，，p2 * k2）(其中k2=N/p2)，，，（pk，pk * 2，，，pk * kk）(其中kk=N/pk)，总共有这么多个；

所以1~N中与N互质的数的个数为：N-N/p1-N/p2-...-N/pk，这样就完了吗？

当然不是，因为这里我们需要减去1~N中与N不互质的数，这里可能存在p1的倍数同时也是p2的倍数的情况即p1 * i=p2 * j的情况，这样的话对于p1 * i我们就多减了一次所以得加回来，这样的数有多少个呢？对于p1，p2的公共倍数总共有N/(p1 * p2)个它们被减了两次所以得加回来，同理对于p1，p3的公共倍数，对于p1，p4的公共倍数，，，也是同样的处理，所以最后的结果为：N-N/p1-N/p2-...-N/pk + N/(p1 * p2) + N/(p1 * p3) +...，这样就完了吗？

当然不是，这里可能存在一个数它是p1，p2，p3三者的公共倍数的情况，这样的数我们首先减去了三次，然后又因为它是p1 * p2的倍数、又因为它是p1 * p3的倍数、又因为它是p2 * p3的倍数，所以我们又减去了三次所以最后我们相当于一次没有减去，所以这里我们得减去它，这样的数有多少个呢？对于p1，p2，p3的公共倍数总共有N/(p1 * p2 * p3)个它们一次都没有减所以得减回来；同理对于p1，p3，p4三者的公共倍数的情况，对于p1，p3，p5三者的公共倍数的情况，，，也是同样的处理，所以最后的结果为：N-N/p1-N/p2-...-N/pk + N/(p1 * p2) + N/(p1 * p3) +...，-N/(p1 * p2 * p3)-N/(p1 * p2 * p4)-...-，后面的情况依此类推，后面会遇到类似p1，p2，p3，p4四者的公共倍数的情况，，，直到最后遇到p1，p2，p3，，，pk总共k个数的公共倍数的情况，

**所以最后的结果为：**

**N * (1-1/p1) * (1-1/p2) * (1-1/p3) * ... * (1-pk)**

**将其展开，对 (1-1/p1) * (1-1/p2) * (1-1/p3) * ... * (1-pk)的每一项都会提取出一部分，如果这些式子中只提取一项，即：1/pi项则其他式子提取的是1，最后1/pi的系数是-1；如果这些式子中提起出两项，即：1/pi * 1/pj则其他式子提取的是1，最后1/pi * 1/pj的系数是1，，，**

### （874）筛法求欧拉函数

![1690704512708](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690704512708.png)

解题思路：

#### 是什么：

类似于前面的由筛法求1~n中质数的过程，这里我们由筛法求1~n中每个数的欧拉函数

#### 为什么：

如果对1~n中每个数应用一次欧拉函数那么计算过程会非常复杂，所以我们想到用筛法来求欧拉函数

#### 怎么办：

##### 如何用筛法求欧拉函数呢？

回忆一下之前我们在哪里用过筛法？那就是用筛法求质数的过程，可是这里是用筛法来求欧拉函数，所以我们就看质数能否与欧拉函数挂上什么联系？

类似于筛法求质数的过程中我们用一个数组primes[]来由小到大存储1~n中所有的质数，稍后会由小到大遍历这些质数。

（1）当n是质数时，此时n=primes[j]（primes[j]表示是某个质数），此时1~n中与n互质的数的个数是n-1个，即：euler(n)=n-1

（2）当n不是质数时，此时n可以表示为：n=primes[j] * i（primes[j]表示n的最小质因子，i表明n是该最小质因子的倍数），对此时的i进行分解质因数：i=p1^a1 * p2^a2 * ... * pk^ak（其中p1，p2，，，pk为质数，并且由小到大排列），则此时根据primes[j]与i的关系进行分类讨论：

​			①当i%primes[j]==0时，说明此时primes[j]是i的最小质因子，即此时primes[j]=p1，然后对n进行分解质因数：n=primes[j] * i=primes[j] *（p1^a1 * p2^a2 * ... * pk^ak）=（p1^(a1+1) * p2^a2 * ... * pk^ak）根据欧拉函数此时的euler[n]=n * (1-1/p1) * (1-1/p2) * ... * (1-1/pk)=primes[j] * i * (1-1/p1) * (1-1/p2) * ... * (1-1/pk)，其中 i * (1-1/p1) * (1-1/p2) * ... * (1-1/pk)=euler(i)（就是i对应的欧拉函数），所以上述euler(n)=euler(i) * primes[j]

​			②当i%primes[j]!=0时，说明此时primes[j]小于i的最小质因子，即此时primes[j]<p1，然后对n进行分解质因数：n=primes[j] * i=primes[j] *（p1^a1 * p2^a2 * ... * pk^ak）根据欧拉函数此时的euler[n]=n * (1-1/primes[j]) * (1-1/p1) * (1-1/p2) * ... * (1-1/pk)=primes[j] * i * (1-1/primes[j]) * (1-1/p1) * (1-1/p2) * ... * (1-1/pk)，其中 i * (1-1/p1) * (1-1/p2) * ... * (1-1/pk)=euler(i)（就是i对应的欧拉函数），primes[j] * (1-1/primes[j])=(primes[j]-1)，所以上述euler(n)=euler(i) * (primes[j]-1)

**综上，通过筛法我们得到了一种类似递推的关系来求解欧拉函数**

##### long型数据是什么？

在Java中，long 是一种基本数据类型，用于表示长整型数据。

`Long` 使用 64 位来存储整数值，因此它可以表示更大范围的整数值，相比 `int` 类型更大。

`Long` 的取值范围是从 -9,223,372,036,854,775,808（-2^63）到 9,223,372,036,854,775,807（2^63-1）。

##### notes：针对整型数据同时又超过int型范围，就可以使用long型数据

```Java
import java.util.*;
public class Main{
    static int N=1000010,cnt;
    static int[] primes=new int[N];
    static boolean[] st=new boolean[N];
    static int[] euler=new int[N];//euler[i]用于记录数字i的欧拉函数
    static void getEuler(int n){
        euler[1]=1;//1的欧拉函数是1
        for(int i=2;i<=n;i++){
            if(!st[i]){
                primes[cnt++]=i;
                euler[i]=i-1;//如果i是质数，那么i对应的欧拉函数是i-1
            }
            for(int j=0;primes[j]<=n/i;j++){
                st[primes[j]*i]=true;
                if(i%primes[j]==0){
                    euler[primes[j]*i]=euler[i]*primes[j];
                    break;
                }
                euler[primes[j]*i]=euler[i]*(primes[j]-1);
            }
        }
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        getEuler(n);
        // int res=0;这里如果用int型数据一直相加会造成数据溢出，所以得换成long型数据
        long res=0;
        for(int i=1;i<=n;i++){
            res+=euler[i];
        }
        System.out.println(res);
    }
}
```





## 4、快速幂

### 是什么：

是一种快速求幂函数的操作

### 为什么：

普通的方法求a^n需要循环n次，每次进行乘a操作，时间复杂度为O(n)太麻烦了，通过快速幂的方法求结果时间复杂度为O(logn)

### 怎么办：

#### 如何求快速幂呢？

（1）将原本的指数分解成二进制的形式

（2）将原本的幂函数分解成多个幂函数的乘积的形式，然后通过这些多个幂函数的乘积得到原来的幂函数的值（通过此方法就避免了对原来的幂函数需要循环n次进行求解的步骤，值得注意的是这里被分解成的多个幂函数的求解是通过彼此间存在平方关系进行求解的，而不是简单的循环进行求解，下面会介绍）

#### 如何将幂函数a^n分解成多个幂函数的乘积的形式呢？

假设指数n在十进制下的表示为（15）在二进制下的表示为（1111），即此时n=2^3 + 2^2 + 2^1 +2^0，此时的幂函数a^n=a^(2^3 + 2^2 + 2^1 +2^0)=a^(2^3) * a^(2^2) * a^(2^1) * a^(2^0)，此时要计算a^n的话我们可以先计算a^(2^0)，再计算a^(2^1)，再计算a^(2^2)，再计算a^(2^3)，注意这里存在关系：a^(2^(i+1))=a^(2^i * 2)=(a^(2^i))^2，即后一项是前一项的平方，所以这里原本要求解a^15要循环15次，但是现在我们只要求解a^(2^0)、a^(2^1)、a^(2^2)、a^(2^3)就可以了，时间复杂度为O(logn)

### （876）快速幂求逆元

![1690958815945](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690958815945.png)

解题思路：

#### 是什么：

如果存在a，b使得(a*b) mod p=1（也可以写作 a * b ≡ 1(mod p)， 其中 '≡' 表示同余关系即：

(a * b) mod p=1 mod p，则称数b就是数a在模p情况下的逆元。

#### 为什么：

因为**取模运算对于加法、减法、乘法都具有传递性，但是对于除法不具有传递性**，即：

（a+b）%p=a%p+b%p（ 以防这里a%p+b%p的结果超过p，所以这里再对p取余，

写作（a+b）%p=(a%p+b%p)%p ）

（a-b）%p=a%p-b%p(  以防这里a%p-b%p的结果超过p，所以这里再对p取余，

写作（a-b）%p=(a%p-b%p)%p  )

（a * b）%p=a%p * b%p(  以防这里a%p * b%p的结果超过p，所以这里再对p取余，

写作（a * b）%p=(a%p * b%p)%p  )

但是（a/b）%p = a%p / b%p不成立，很容易证明，取反例就行：a=20,b=10,p=4

则此时

（a/b）%p=(20/10)%4=2，

a%p / b%p=20%4 / 10%4=0

二者并不相等。

所以当遇到一个运算该运算结果很大会导致数据溢出的时候是必定要取模的，但是假如该运算过程中涉及到除法，而除法不具备对取模运算的传递性，这时候又该怎么办？

这时候逆元就派上用场了，利用逆元将除法运算转换成乘法运算，这时对于取模运算就具有传递性了，详见下面公式：

假设inv(b)是b关于模p的逆元，即：(b * inv(b)) %p=1

(a/b)%p=(a/b * b * inv(b))%p=(a * inv(b))%p，至此就将除法运算转换成乘法运算（乘法运算对于取模具有传递性），

(a/b)%p=(a/b * b * inv(b))%p这一步为什么成立？

因为这里是对p做取模运算，而(b * inv(b)) %p=1，所以对于(a/b)%p来说给它乘以一个 b * inv(b)再对p取模结果不变，即：(a/b * b * inv(b))%p=(a/b)%p * (b * inv(b))%p=(a/b)%p*1，结果当然是不变的

#### 怎么办：

##### 如何求逆元呢？

上述介绍了逆元的用途，当给定数a和数p以后如何求数a关于模p的逆元呢？

##### 欧拉定理：

**当数a与数p互质的时候，此时a^euler(p)=1(mod p)（其中euler(p)表示p的欧拉函数）**

###### ①欧拉定理为什么成立？

根据欧拉函数1~n中存在euler(n)个与n互质的数，假设这euler(n)个数就是：a1,a2,a3,,,aeuler(n)（**注意这里对于任意的ai来说ai%n=ai，而且这里的ai,aj两两互不相同**），那么对于a * a1，a * a2，a * a3，,,,a * aeuler(n)这euler(n)个数来说也是和数n互质的（**因为a和n互质，ai和n互质，所以a * ai和n互质**），并且这里的a * ai和a * aj对n取模的结果两两各不相同，为什么？反证法证明如下：

假设(a * ai) %n=(a * aj) %n

那么(a * (ai-aj))%n=0，即a%n * (ai-aj)%n=0

又因为a与n互质，所以a%n!=0

所以(ai-aj)%n=0，即ai%n-aj%n=0，ai%n=aj%n（这里对于任意的ai来说ai%n=ai，所以这里可以得到ai=aj）

这与前述提到的ai,aj两两互不相同矛盾。所以我们可以得到这里的a * ai和a * aj对n取模的结果两两各不相同

又因为一个数模n的结果一定在0~n-1范围内，而且0~n-1范围内与n互质的数又是固定的，所以这里的a1,a2,a3,,,aeuler(n)关于n取模得到的结果集一定和a * a1，a * a2，a * a3，,,,a * aeuler(n)关于n取模得到的结果集相同，只是二者的顺序可能有所不同（比如：ai%n=(a * aj)%n这样），所以(a1 * a2 * a3,,,* aeuler(n))%n的结果等于((a * a1) * (a * a2) * (a * a3) * ,,,(a * aeuler(n)))%n的结果，而((a * a1) * (a * a2) * (a * a3) * ,,,(a * aeuler(n)))%n=（a^euler(n) * (a1 * a2 * a3,,,* aeuler(n))）%n=a^euler(n) %n * (a1 * a2 * a3,,,* aeuler(n))%n，

所以a^euler(n) %n =1，欧拉定理得证

###### ②欧拉定理为什么要强调数a与数p互质？

因为上述的证明过程要用到a与p互质的条件

##### 费马小定理：

由前面我们得到欧拉定理如下：

**当数a与数p互质的时候，此时a^euler(p)=1(mod p)（其中euler(p)表示p的欧拉函数）**

这里当p是一个质数的时候，euler(p)=p-1，此时的欧拉定理就变成了a^(p-1)=1(mod p)，即a * a^(p-2)=1(mod p)

即此时a^(p-2)就相当于数a模p的逆元。

在这种情况下我们就将找逆元的操作转换成求幂函数的操作

notes:费马小定理为什么要强调a不能被p整除？

因为假如a能被p整除的话，那么a乘以任何一个数都能被p整除自然就不存在取余了

![1690959074394](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1690959074394.png)

```Java
import java.util.*;
public class Main{
    //计算a^bmodp的结果的函数（快速幂函数）
    static void qmi(int a,int b,int p){
        if(a%p==0){
            System.out.println("impossible");
            return;
        }else{//利用快速幂计算a^b%p
            long res=1;
            while(b!=0){
                if((b&1)==1){
                    res=res*a%p;  
                }
                a=(int)((long)a*a%p);
                b>>=1;
            }
            System.out.println(res);
        }
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        for(int i=1;i<=n;i++){
            int a=sc.nextInt();
            int p=sc.nextInt();
            qmi(a,p-2,p);
        }
    }
}
```

## 5、扩展欧几里得算法

### 是什么：

传统的欧几里得算法即辗转相除法是用来求两个数的最大公因子的，而扩展欧几里得算法在求解两个数的最大公因子的同时还可以找到满足裴蜀定理的系数（以此为基础就可以用来求解线性同余方程）

### 为什么：

可以用来求解裴蜀定理的系数

#### notes：裴蜀定理

##### 是什么：

对于任意的正整数a,b一定存在非零整数x,y（可以为负），使得a * x+b * y=gcd(a,b)（a,b的最大公因子）成立，而且gcd(a,b)是此方程能凑成的最小正数。

为什么gcd(a,b)是此方程能凑成的最小正数？

因为a是gcd(a,b)的倍数，所以a * x是gcd(a,b)的倍数，对于b * y也是同理，所以a * x+b * y一定是gcd(a,b)的倍数，最小就是一倍了，所以gcd(a,b)是此方程能凑成的最小正数。

如何证明裴蜀定理呢？

对于任意给定的a,b，只要我们找到一组x,y使得a * x+b * y=gcd(a,b)成立则裴蜀定理得证，如何找到这样一组x,y呢？就是通过扩展欧几里得算法。

### 怎么办：

#### 如何使用扩展欧几里得算法呢？

现在要求使得a * x+b * y=gcd(a,b)成立的x,y

（1）当b=0时，此时式子转换为a * x+0 * y=a

直接可以得到该方程的一组解为x=1,y=0

（2）当b!=0时，此时这个式子不好解，但是由前面的欧几里得算法我们知道gcd(a,b)=gcd(b,a%b)，假设我们知道b * x'+(a%b) * y'=gcd(b,a%b)的解x',y'的话，那么对于我们求解a * x+b * y=gcd(a,b)会有帮助，而解决

b * x'+(a%b) * y'=gcd(b,a%b)相对于原问题更简单一点。

为什么会更简单一点？

因为原问题求解gcd(a,b)现在转换为求解gcd(b,a%b)，如果依然不好求的话则可以继续转换令a'=b,b'=a%b，则gcd(b,a%b)=gcd(a',b')=gcd(b',a'%b')，一直这样递归直到b=0时此时可以直接求解。

现在我们知道了对于该式子可以递归求解，但是递归求解的是下一层的结果，它和当前层求解的结果之间存在什么关系呢？即a * x+b * y=gcd(a,b)的解x,y和b * x'+(a%b) * y'=gcd(b,a%b)的解x',y'之间存在什么关系呢？

对于b * x'+(a%b) * y'=gcd(b,a%b) 

——>b * x' + (a- ⌊a/b⌋ * b ) * y'=gcd(b,a%b)

——>b * x' + (a- ⌊a/b⌋ * b ) * y'=gcd(a,b)

——>a * y' + b * (x' - ⌊a/b⌋ * y') = gcd(a,b)

即x=y'，y=x' - ⌊a/b⌋ * y'二者的解之间存在这样的关系，所以只要我们求得x',y'就能求得x,y



### （877）扩展欧几里得算法

扩展欧几里得算法的应用

### （878）线性同余方程

![1691570105138](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1691570105138.png)

解题思路：

#### 是什么：

针对a * x ≡ d(mod b)情况下的解x就是线性同余方程的解

#### 怎么办：

如何求解线性同余方程？

a * x ≡ d(mod b)转换为

——>a * x = b * (-y) + d

——>a * x + b * y = d

将原问题转换为扩展欧几里得算法可以应用的问题，不过这里有一点需要注意的是扩展欧几里得算法的形式：

a * x + b * y = gcd(a,b)（等号右边是a,b的最大公约数）

而这里的形式为：a * x + b * y = d（等号右边是常数d）所以

如果gcd(a,b)|d（即d不是gcd(a,b)的倍数），则上述扩展欧几里得算法无解；

如果gcd(a,b)|d（即d是gcd(a,b)的倍数），则a * x + b * y = d的解假设为x'（注意这里只要求x不需要求y），则x'和扩展欧几里得算法的解之间存在如下关系：x'=x * (d/gcd(a,b))（**为什么存在这个式子？因为这里的是线性方程，当方程右边扩大了d/gcd(a,b)倍以后方程的左边也得扩大d/gcd(a,b)倍**）

```Java
import java.util.*;
public class Main{
    static int x,y;
    static int exgcd(int a,int b){
        if(b==0){
            x=1;
            y=0;
            return a;
        }else{
            int tmp=exgcd(b,a%b);
            int t=x;//注意这里表示的是递归求解的x',y'和当前x,y之间满足的关系：x=y',y=x'-a/b*y'
            x=y;
            y=t-a/b*y;
            return tmp;
        }
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        for(int i=1;i<=n;i++){
            int a=sc.nextInt();
            int b=sc.nextInt();
            int m=sc.nextInt();
            int d=exgcd(a,m);//d表示a,m的最大公因子
            if(b%d!=0){//如果b不是a,m最大公因子的倍数则扩展欧几里得算法无解
                System.out.println("impossible");  
            }else{
                System.out.println((long)x*b/d%m);
                /*
                注意这里b的范围为1~2*10^9，所以x*b可能会数据溢出，所以得进行数据类型转换为long型。
                
                又因为题目中要求最后的输出结果为int型，而最后的结果x*b/d的结果可能会超出int型范围，
                所以又得对m取模，这里为什么要对m取模？能不能对一个很大的int型数据比如1e9+7取模？
                答案是不能的，因为这里我们求的是a*x=b(mod m)下的解x只是因为这里的x可能会很大
                超出int型范围所以我们得对它进行取模运算，但是取模运算后的结果依然得满足
                a*x=b(mod m)这个条件，所以我们只能选择将x对m取模
                */
            }
        }
    }
}
```





## 6、中国剩余定理

### 是什么：

中国剩余定理可以用来求解一组线性同余方程组的解，传统的扩展欧几里得算法可以用来求解一个线性同余方程的解，而中国剩余定理就是在扩展欧几里得算法的基础上可以用来求解一组线性同余方程组的解

### 怎么办：

#### 如何使用中国剩余定理求解一组线性同余方程组的解呢？

比如说现在有两个线性同余方程：

x=m1(mod a1)

x=m2(mod a2)

如何找到满足条件的x使得上述两个式子成立呢？

**方法1：分别对上述两个式子进行转换，转换成扩展欧几里得算法的形式**

x=m1(mod a1)——>x=a1 * (-y1) + m1——>1 * x + a1 * y1 =m1

x=m2(mod a2)——>x=a2 * (-y2) + m2——>1 * x + a2 * y2 =m2

针对上述两个式子可以分别使用扩展欧几里得算法进行求解（欧几里得算法的形式为：

a * x + b * y = gcd(a,b)），然后求得两个式子各自的解x以后再对它们进行求交集运算，所得结果就是满足条件的解

**方法2：直接将两个式子合并为一个式子（更好）**

因为上述两个式子的左边都是要求解的变量x，右边分别是x需要满足的条件，所以我们直接令右边的两个式子相等可以直接求解变量x：

x=m1(mod a1)——>x=a1 * k1 + m1

x=m2(mod a2)——>x=a2 * k2 + m2

——》a1 * k1 + m1 = a2 * k2 + m2

a1 * k1 - a2 * k2 = m2 - m1

——>a1 * k1 + a2 * (-k2) = m2 - m1

注意对于上述的式子就可以看成是对a1,a2,(m2-m1)的扩展欧几里得算法（要求的解就是这里的k1,k2），假设我们求得一组解k1=k1',k2=k2'然后我们将其带入x的表达式x=a1 * k1 + m1（也可以带入x=a2 * k2 + m2，效果一样的）就能够求得最后的x=a1 * k1' + m1了，但注意这只是x的其中一个解，如何能求出x的通解呢？关键就在于通过如下的式子我们也要求得k1和k2的通解：a1 * k1 + a2 * (-k2) = m2 - m1，对于这个式子当我们求得一个特解k1=k1',k2=k2'以后它的通解为：k1=k1'+k * a2/d（其中k为任意倍数，d=gcd(a1,a2)）,k2=k2'+k * a1/d（将通解带入原式，两边都有一个k * a1 * a2/d，而且正负号相反所以相互抵消）。所以当将两个线性同余方程合并以后我们可以得到它的通解k1=k1'+ k * a2/d，k2=k2'+ k * a1/d（其中k1',k2'为两个线性同余方程合并后求解的特解），我们将通解k1=k1'+ k * a2/d带入x的表达式x=a1 * k1 + m1中得到x的通解为：

**x=a1 * (k1'+k * a2/d) + m1=k1' * a1+m1+k * a1 * a2/d，其中k1' * a1+m1为一个常数(a1,m1是给定的，k1'是通过合并两个式子求得的特解也是一个常数)，而a1 * a2/d为a1,a2的最小公倍数(为什么？别忘了这里的d是a1,a2的最大公约数，通过定义出发，a1,a2的最小公倍数指的是能同时整除a1,a2的最小正整数，而a1 * a2/d刚好满足这个条件啊)，而且a1,a2为给定的常数并且d也是常数(当给定a1,a2以后它们的最大公约数也就确定了)，所以在x=k1' * a1+m1+k * a1 * a2/d中我们令k1' * a1+m1这个常数为m，令a1 * a2/d这个常数为a，所以x的表达式就可以表示为x=m+k * a=a * k+m(这里的a,m都是可以通过已知的两个式子求解的量)，我们发现通过两个式子合并以后求出来的x的通解和原本x所满足的同余方程的形式是一模一样的（x=m1(mod a1)——>x=a1 * k1 + m1，x=m2(mod a2)——>x=a2 * k2 + m2），由此我们可以继续拿着刚刚求出来的通解的式子x=a * k+m继续和别的同余方程进行合并**，这里总共有n个式子我们两两合并，总共合并n-1次，最后就得到了一个线性同余方程x=a * k + m，通过扩展欧几里得算法就可以得到这一个线性同余方程的解，又因为这个式子的得来过程中是满足同余方程两两合并的条件的所以它本身也是满足各自的线性同余方程的，所以这个解就是线性同余方程组的解。

这种解法相对于上述方法1的好处是不需要再去求两个解集的交集了（交集不好求，总不能将解集各自遍历一遍吧）

### （204）表达整数的奇怪方式

![1691765531487](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1691765531487.png)

解题思路：

中国剩余定理的使用，这里有一个注意点就是题目中要求的是满足线性同余方程组的最小的非负整数解，所以这里当合并求解线性同余方程的时候我们就得在通解中寻找最小的非负整数解了，如何求最小非负整数解是一个问题

```Java
import java.util.*;
public class Main{
    static long k1,k2;//用于记录线性同余方程的解
    static long exgcd(long a,long b){
        if(b==0){
            k1=1;
            k2=0;
            return a;
        }else{
            long tmp=exgcd(b,a%b);
            long t=k1;
            k1=k2;
            k2=t-a/b*k2;
            return tmp;
        }
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        long a1=sc.nextInt();
        long m1=sc.nextInt();
        boolean has_ans=true;//用于记录两个同余方程是否有解
        for(int i=2;i<=n;i++){
            long a2=sc.nextInt();
            long m2=sc.nextInt();
            long d=exgcd(a1,a2);
            if((m2-m1)%d!=0){
                //如果m2-m1不是d的倍数(这里的d是gcd(a1,a2))则对应的方程a1*k1+a2*k2=m2-m1无解
                has_ans=false;
                break;
            }else{
                k1=k1*(m2-m1)/d;
                /*
                因为扩展欧几里得算法对应方程a1*k1+a2*k2=d的右边为d，
                而这里的方程a1*k1+a2*k2=m2-m1的右边为m2-m1，
                所以我们得将扩展欧几里得算法得到的解扩大(m2-m1)/d倍
                */
                
                long t=a2/d;
                /*
                上述得到的k1为扩展欧几里得算法得到的一个特解，而我们要求的通解为
                k1'=k1+k*a2/d（其中k为任意整数，d为gcd(a1,a2)）
                为什么要求通解呢？
                因为我们要求的是满足条件的最小的非负整数解，所以得在通解中进一步筛选
                如何筛选出最小的非负整数解呢？
                方法1：将所得特解k1带入然后一个一个试验k的取值看看是否满足最小的
                非负整数的条件（太麻烦）
                
                方法2：注意观察上述通解k1'的形式：k1'=k1+k*a2/d
                令a2/d=t，则k1'=k1+k*t，我们发现通解为t的倍数加上k1的这种形式，
                (1)当k1很大时，此时为了得到最小的非负整数解可以将k取为负数，适当减小k1(最小可以减
                为多少呢？就是当k=-(k1/t)（注意这里是向下取整）的时候，此时k1'=k1%t，
                怎么得到该解的？我们令k1+k*t=0得到此时k的取值然后稍微放大k的取值使得k1+k*t>0),
                (2)当k1为负数时，此时为了得到最小的非负整数解可以将k取为正数，适当增大k1(最大可以增
                为多少呢？就是当k=-(k1/t)+1的时候，此时k1'=k1+[-(k1/t)+1]*t=k1-(k1/t)*t+t，
                注意这里(k1/t)是向下取整除法，所以k1-(k1/t)*t=k1%t,所以最后的结果为k1%t+t),
                那么我们需要根据具体的k1的数值进行判断吗？
                没那么麻烦，我们发现在k1'的通解k1'=k1+k*t中为了得到k1'的最小非负整数解，可以让
                k1'=(k1%t+t)%t就可以了
                */
                k1=(k1%t+t)%t;//这一步是为了保证x为最小非负整数解（x的通解为x=x+kt，其中k为倍数）

                m1=k1*a1+m1;//这是通过合并两个式子得到的新的m，我们将其作为参数继续和同余方程进行合并
                a1=a1*a2/d;//这是通过合并两个式子得到的新的a，我们将其作为参数继续和同余方程进行合并
            }
        }
        if(has_ans==false){
            System.out.println(-1);
        }else{
            /*
            注意上述过程总共会合并n-1个式子，所以最后得到的依然是一个线性同余方程：
            x=a*k+m
            要想得到这个式子的最小非负整数解除了利用扩展欧几里得算法得到x的通解然后再去求其中最小
            的非负整数解以外，还可以仿照上述求k1'=k1+k*t的最小非负整数解的过程令x=(m%a+a)%a
            */
            System.out.println((m1%a1+a1)%a1);
        }
    }
}
```

## 7、高斯消元

### 是什么：

是用于求解线性方程组的一种解法，就是线性代数中将矩阵进行初等行变换得到上三角矩阵（阶梯型矩阵）然后得到方程组的解的办法

### 怎么办：

#### 回忆一下线性代数中如何解线性方程组：

利用初等行变换将矩阵变成阶梯型矩阵，然后将阶梯型矩阵化成最简阶梯型矩阵就能得到答案，举例如下：

矩阵的初等行变换不影响最终的结果，矩阵的初等行变换包括：

（1）矩阵的某一行乘以一个不为0的数

（2）交换矩阵中某两行的位置

（3）将矩阵的某一行乘以一个倍数加到另一行中

![1691984521373](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1691984521373.png)

观察上述过程发现为了使矩阵变成阶梯型我们是不是会遍历每个列然后看怎样才能使该列变成阶梯，然后在该列中寻找主元再利用该主元所在行通过初等行变换将其所在列的其他元素消为0（**这里其实我们不用寻找主元直接以当前行所在列的元素作为主元消去当前列的其他元素，举个例子上述过程中我们想凑成阶梯型矩阵当我们遍历第一列的时候我们直接将第一列第一行的元素作为主元然后用第一行进行初等行变换去消掉第一列其他行的元素，当我们想凑成阶梯型矩阵遍历到第二列的时候我们直接以第二列第二行的元素作为主元然后用第二行进行初等行变换去消掉第二列其他行的元素，，，后续过程类似，直到最后得到最简阶梯型矩阵就得到了答案**）



#### 高斯消元法解线性方程组的步骤：

整体求解过程和线性代数中差不多，但是也有一点区别的地方，上述过程中为了凑成阶梯型矩阵可以随便在当前列中取一个元素作为主元，但是在这里我们最好取当前列中绝对值最大的那个元素作为主元，为什么？因为后续我们肯定会将主元的系数通过初等行变换变为1，这里的系数是用的double类型数据，做浮点数除法的时候显然除以一个大数会让精度更好误差更小（存储double类型数据会有误差，它不像int型数据那样是精确的）

所以高斯消元法求解线性方程组的步骤如下：

（1）遍历每个列，找到当前列中绝对值最大的那个元素作为主元，然后将它所在的行换到矩阵的开头（注意这里的开头不一定是矩阵的第一行，因为当我们遍历第一列的时候找到最大的那个元素将它放到第一行，当我们遍历第二列的时候找到最大的那个元素这时候就要将它放到第二行了）

（2）将当前行的主元对应的系数通过初等行变换变为1

（3）通过初等行变换将主元所在列的其他元素的系数消为0

（4）重复上述过程，此时就可以得到阶梯型矩阵了（注意此时得到的仅仅是阶梯型矩阵(上三角形式)，还不是最简阶梯型矩阵(只有主元对应的位置有系数，主元所在列的其他行系数都为0)）

### （883）高斯消元解线性方程组

解题思路：

高斯消元法解线性方程组的应用，注意这里会存在某一列没法构成阶梯的情况（**为什么要关注某一列能否构成阶梯的情况呢？因为这涉及到矩阵的秩，也就是方程组的解的情况**），具体如下图所示

![1692001494179](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1692001494179.png)



notes：这里输入的数是浮点数，我们要判断的是浮点数的绝对值，在C++中判断整数的绝对值用的是Math库中的abs()函数，判断浮点数的绝对值用的是Math库中的fabs()函数；而在java中不管是整数还是浮点数统一用的都是Math库中的abs()函数

```Java
import java.util.*;
public class Main{
    static int N=110,n;
    static double[][] a=new double[N][N];
    static double eps=1e-6;
    /*
    注意double类型的数据存储是有误差的，不像int型数据存储是精确的，
    判断double类型的数据等于0只要满足该数据小于一个很小的值就可以了（该值就是1e-6），
    如果我们直接用该数据等于0是没法判断的
    */
    
    static void swap(int t,int r,int j){
        double tmp=a[t][j];
        a[t][j]=a[r][j];
        a[r][j]=tmp;
    }
    static int gauss(){
        int c,r;//c表示当前遍历到第c列，r表示当前遍历到第r行
        for(c=1,r=1;c<=n;c++){
            int t=r;//用t来记录第c列中绝对值最大的数在第t行
            for(int i=r;i<=n;i++){
                if(Math.abs(a[i][c])>Math.abs(a[t][c])){
                    t=i;
                }
            }
            if(Math.abs(a[t][c])<eps){
                /*
                如果第c列绝对值最大的数的绝对值为0的话，就说明第c列没法构成阶梯。
                前面说过了double型数据存储有误差，所以判断0的话就是小于一个很小的数就行了。
                */
                continue;
            }
            for(int j=c;j<=n+1;j++){
                /*
                将第c列绝对值最大的数所在的第t行换到矩阵头部（也就是当前正在遍历的矩阵的第r行），
                但是这里明明是将主元所在的第t行的第c列~第n+1列这一段换到矩阵头部啊，并不是将
                整个第t行换到矩阵头部，理论上应该是将整个第t行换到矩阵头部的，这样不会有问题吗？
                
                没有问题，后面会说明为什么我们不必将整个第t行全部换到矩阵头部（因为后续我们将
                第1列主元所在的行换到矩阵头部以后会接着利用初等行变换将第1列的其他行元素全部
                变为0，然后找到第2列主元所在的行假设为第i行将第i行换到矩阵头部的过程中此时该
                矩阵中第1列的元素除了第1行以外其他全部都是0所以我们在将第i行移到矩阵头部的过
                程中也没必要再把第i行第1列的元素移上去了），后续也是同理
                */
                swap(t,r,j);
            }
            for(int j=n+1;j>=c;j--){
                //将主元的系数利用初等行变换变为1
                a[r][j]/=a[r][c];
            }
            
            /*
            利用当前遍历的主元将主元所在列的其他元素的系数通过初等行变换变为0
            这是什么意思呢？
            比如说现在遍历到第1列，然后我们选定第1列绝对值最大的元素然后将它所在的行换到
            矩阵第1行，接着我们再将第1列主元的系数通过初等行变换变为1，紧接着我们再利用
            初等行变换将第1列其他行的元素变为0；
            
            接着我们遍历第2列继续找主元，假设主元所在的为第i行，接着得将第i行换到矩阵第2行，
            注意这时候矩阵中第1列的元素除了第1行以外别的元素已经全部都变为0了，因为前面我们
            刚刚才做的操作将第1列的主元以外的元素的系数变为0，所以此时我们再将第i行换到矩阵
            头部的话已经不需要再将第i行的全部元素换到矩阵头部了（即使换了全部元素的话，第i行
            第1列和第2行第1列的元素也都是0，换了和没换一个样），然后我们将第2列的主元的系数
            通过初等行变换变为1，紧接着我们再利用初等行变换将第2列其他行的元素变为0；
            
            接着遍历第3列继续找主元，假设主元所在的为第j行，接着得将第j行换到矩阵第3行，
            注意这时候矩阵中第1列的元素除了第1行以外别的元素已经全部都变为0了，而且矩阵中
            第2列的元素除了第2行以外别的元素已经全部都变为0了，因为前面我们刚刚才做的操作
            将第1列的主元以外的元素的系数变为0，将第2列的主元以外的元素的系数变为0，所以此时
            我们再将第j行换到矩阵头部的话已经不需要再将第j行的全部元素换到矩阵头部了（即使换了
            全部元素的话，第j行第1列、第2列和第3行第1列、第2列的元素也都是0，换了和没换一个样），
            然后我们将第3列的主元的系数通过初等行变换变为1，紧接着我们再利用初等行变换将第3列
            其他行的元素变为0；
            
            继续重复上述过程
            */
            for(int i=r+1;i<=n;i++){
                if(Math.abs(a[i][c])>eps){
                    for(int j=n+1;j>=c;j--){
                        a[i][j]-=a[r][j]*a[i][c];
                    }
                }
            }
            r++;
        }
        
        if(r<=n){
            /*
            如果r<=n的话说明该矩阵的前n列中有几列没法构成阶梯，也就是说该矩阵的秩小于n
            此时方程组无解或有无数组解（就相当于矩阵的秩小于n）
            
            为什么这里是r<=n代表该矩阵的秩小于n呢？而不是r<n代表该矩阵的秩小于n呢？
            因为这里的r一开始是从1开始的而不是从0开始的
            */
            for(int i=r;i<=n;i++){
                /*
                判断系数矩阵的秩和增广矩阵的秩
                经过上述过程此时系数矩阵中第r行~第n行的系数已经全部为0了，如果第r行~第n行
                中有某一行的常数列不为0的话则说明此时系数矩阵的秩小于增广矩阵的秩，该方程组
                无解，否则的话有无数组解
                */
                if(Math.abs(a[i][n+1])>eps){
                    return 2;//方程组无解
                }
            }
            return 1;//该方程组有无数组解
        }else{
            /*
            如果r>n的话说明该矩阵的前n列中每一列都可以构成阶梯，也就是说此时矩阵的秩为n
            此时系数矩阵的秩等于增广矩阵的秩等于n，该方程组有唯一一组解
            
            经过上述过程我们已经得到了阶梯型矩阵，接下来我们就要将其化为最简阶梯型矩阵得到
            方程组的解
            */
            for(int i=n;i>=1;i--){
                for(int j=i+1;j<=n;j++){
                    a[i][n+1]-=a[i][j]*a[j][n+1];
                }
            }
        }
        return 0;
    }
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        n=sc.nextInt();
        for(int i=1;i<=n;i++){
            for(int j=1;j<=n+1;j++){
                a[i][j]=sc.nextDouble();
            }
        }
        int t=gauss();
        if(t==2){
            System.out.println("No solution");
        }else if(t==1){
            System.out.println("Infinite group solutions");
        }else{
            for(int i=1;i<=n;i++){
                System.out.printf("%.2f\n",a[i][n+1]);
            }
        }
    }
}
```

## 8、组合数

### 是什么：

组合数（Combinations）就是排列组合中的组合数C(a,b)，表示从a个元素中取b个元素总共有多少种不同的取法。在组合数中，元素的顺序不重要，只考虑元素的选取情况。

组合数通常用记号 "C(a, b)"表示，其中 a 表示总共有多少个元素，b 表示要选择多少个元素。组合数可以用数学公式计算，公式如下：

C(a,b)=A(a,b)/A(b,b)

其中：A(a,b)=a * (a-1) * (a-2) * (a-b+1) = a * (a-1) * (a-2) * (a-b+1) * (a-b) * (a-b-1) * ... *1 /  (a-b) * (a-b-1) * ... *1=a!/(a-b)!，A(b,b)=b!

所以C(a,b) = a!/（b! * (a-b)!）

### 怎么办：

#### 组合数的性质①：C(n,0)=1

#### 组合数的性质②：C(a,b)=C(a-1,b)+C(a-1,b-1)

如何理解上述性质②？

可以这样理解，总共有a个苹果现在想从中取出b个苹果，总共有多少种取法？

当要在a个苹果中取出b个苹果的过程中现在我们关注a个苹果中的第i个苹果，它只有两种状态：要么被取，要么不取，有且仅有这两种状态。

①当第i个苹果被取的时候，现在我们只要在剩下a-1个苹果中取出b-1个苹果就行了即C(a-1,b-1)

②当第i个苹果不取的时候，现在我们要在剩下的a-1个苹果中取出b个苹果就行了即C(a-1,b)

当要在a个苹果中取出b个苹果的时候有且仅有上述两种状态即：C(a,b)=C(a-1,b)+C(a-1,b-1)

### （885）求组合数1

解题思路：

#### 怎么办：

##### 解法一：暴力法

注意这里每次输入一组a,b的时候我们当然可以用暴力法C(a,b)=a!/（b! * (a-b)!）每次都重新计算C(a,b)，但是这样太麻烦了，因为这里的a,b的范围最大为2000，所以每次计算一组C(a,b)最多进行2000次运算（因为C(a,b)=a!/（b! * (a-b)!）要计算a!），总共会进行n=10000次询问，所以总共的运算次数为10000 * 2000=2 * 10^7；

##### 解法二：预处理法得到每一组C(a,b)的值

注意看这里的a,b的范围小于等于2000，而且这里还有组合数的性质②，也就是说我们事先通过预处理将所有的C(a,b)的值都求完存储在数组中然后当要查询一组C(a,b)的值的时候直接去查表（查表的时间可以忽略）所需要的运算次数也仅仅为2000^2 = 4 * 10^6（这里2000^2怎么来的？这里a的取值总共有最多2000种，b的取值最多有2000种，所以C(a,b)的运算最多只有2000 * 2000种可能）

### （886）求组合数2

![1692676349216](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1692676349216.png)

解题思路：

#### 怎么办：

##### 解法一：沿用上题的做法（行不通）

##### 解法二：根据公式C(a,b) = a!/（b! * (a-b)!）计算组合数

方法是可行的，但是有以下几个注意点：

①如果我们每次都要重新计算a!的话未免也太麻烦了

所以我们可以事先计算好所有a!的值并存储在一个一维数组fact[]中（**fact[i]表示i的阶乘的值**），后续要用到a!的时候直接去数组中调用fact[a]即可

②因为这里a,b的值特别大所以C(a,b)的值会出现整数溢出的情况所以需要对1e9+7取模

也就是说我们需要对a!/（b! * (a-b)!）这个式子进行取模运算，但是由前面我们知道**取模运算对于除法不具有传递性**，所以针对[a!/（b! * (a-b)!）]%(1e9+7)，我们需要找到b!关于模1e9+7的逆元，同时也需要找到(a-b)!关于模1e9+7的逆元，然后就将除法取模运算转换为了乘法取模运算，所以我们另外还需要一个数组infact[]专门用来存储各个数的阶乘关于模1e9+7的逆元（**infact[i]表示i的阶乘关于模1e9+7的逆元的值**）；最后[a!/（b! * (a-b)!）]%(1e9+7)就可以直接调用fact[]数组和infact[]数组中的元素进行求解了：

[a!/（b! * (a-b)!）]%(1e9+7)=[fact[a] * infact[b] * infact[a-b]]%(1e9+7)，取模运算对于乘法具有传递性

③针对[a!/（b! * (a-b)!）]%(1e9+7)这个式子为什么要进行求逆元操作？

**直接算出a!，b!，(a-b)!三者的结果然后进行除法运算再求该除法运算的结果取模的值不行吗？当然不行，因为这里a!可能已经溢出int型范围了（我们在计算a!的时候已经在考虑这个问题了，所以在计算a!的时候就要进行取模运算了，也就是说后续我们得到的a!的值本身就是已经进行过取模运算后的结果了）**，所以我们必须得先对a!取模但是因为取模运算对于除法又不具有传递性所以这里我们必须进行求逆元的操作。

#### notes：注意整数溢出的问题

a是int型数据，b是int型数据，a*b溢出int型范围，则此时对 a * b进行取模运算：a *b %p(其中p=1e9+7)还有意义吗？

没有意义，因为此时**a *b已经溢出int型范围了，再对它们的乘积取模已经没有意义了**；那么对于该问题应该如何处理得到我们想要的结果？

我们可以将int型数据强制类型转换为long型数据，然后再执行同样的操作就可以了：(long)a *b%p

```Java
//解法二：行得通
import java.util.*;
public class Main{
    static int N=100010,mod=(int)1e9+7;
    static int[] fact=new int[N];//fact[i]用于记录i的阶乘
    static int[] infact=new int[N];//infact[i]用于记录i的阶乘关于模p的逆元（这里的p就是1e9+7）
    static long qmi(int a,int b,int p){//用于求a^bmodp的快速幂操作，用于后续快速幂求逆元操作
        long res=1;
        while(b!=0){
            if((b&1)!=0){
                res=res*a%p;
            }
            a=(int)((long)a*a%p);
            b>>=1;
        }
        return res;
    }
```

```Java
public class Main{
    static long qmi(long a,long b,int p){
        //利用快速幂计算a^bmodp的值，后续会用到这里的快速幂来计算逆元
        long res=1;

            if((b&1)!=0){
                res=res*a%p;
            }            
            a=a*a%p;
            b>>=1;
        }
        return res;
    }
    static int c(long a,long b,int p){
        //利用c(a,b)=[a*(a-1)*...*(a-b+1)]/b!的公式计算c(a,b)的值
        if(b>a){

        }else{
            int res=1;
            for(long i=a,j=1;j<=b;j++,i--){
                res=(int)(res*i%p);
                res=(int)(res*qmi(j,p-2,p)%p);//这里利用快速幂计算逆元
            }
            return res;
        }
    }

        if(a<p && b<p){
            return c(a,b,p);
        }else{
            return (int)((long)c(a%p,b%p,p)*lucas(a/p,b/p,p)%p);
        }
```

### （888）求组合数4

![1693402577680](%E7%AC%AC%E5%9B%9B%E7%AB%A0%E6%95%B0%E5%AD%A6%E7%9F%A5%E8%AF%86.assets/1693402577680.png)

解题思路：

#### 为什么：

这里给定的a,b的值很大，而且要求的是C(a,b)直接的结果而不是对某个数取余之后的结果，所以这里前面的几种做法都行不通了，这里需要使用高精度算法计算组合数

#### 怎么办：

##### 如何计算组合数C(a,b)?

因为这里的a,b的值都很大而且不能取余，所以没法像求组合数1一样通过预处理得到每一组C(a,b)的值；也没法像求组合数2一样利用一维数组fact[i]存储好i! mod p的值；也没法像求组合数3一样利用卢卡斯定理（因为卢卡斯定理也是要取模的）；所以这里我们只能利用高精度计算来求解

根据公式C(a,b)=a!/ (b! * (a-b)!) ，的确我们可以利用高精度乘法先得到a!的值存储在一个集合中，然后再利用高精度乘法得到b! * (a-b)!的值存储在另一个集合中，但是接下来就没法做了，因为我们没法利用高精度除法计算 A/B的值（这里的A,B都是大整数），我们学过的高精度除法针对的是A/b这种情况（这里A是大整数，b是普通整数）。所以我们该如何计算a!/ (b! * (a-b)!) 的值呢？

这里我们可以利用分解质因数，首先将a!分解为：a!=p1^k1 * p2^k2 *... *pn^kn，然后同样的道理将b!,(a-b)!进行分解质因数：b!=p1^k1' * p2^k2' * ... *pn^kn'，(a-b)!=p1^k1'' * p2^k2'' * ... *pn^kn''，所以此时

a!/ (b! * (a-b)!) =p1^α1 * p2^α2 *... *pn^αn（其中α1=k1-k1'-k1''），对于p1^α1 * p2^α2 *... *pn^αn这个式子就可以利用高精度乘法进行计算了

##### 对于p1^α1 * p2^α2 *... *pn^αn这个式子如何找到这里的pi,αi？

首先我们要知道这里的pi，αi代表什么？这里的pi就是对a!,b!,(a-b)!进行分解质因数后的质因数，所以为了得到这里的pi首先我们得找到1~a中所有的质数，这里就利用线性筛法就可以了；找到了1~a中所有的质数以后呢？还是没法从这些质数中挑选出哪些是构成a!的因子，回忆一下当初我们是如何对a进行分解质因数的：用试除法分解质因数，我们遍历从2到n-1的所有数看看a能否被当前遍历到的数整除，如果能的话我们就让a除以当前遍历到的数i，如果(a/i)依然能被i整除的话我们就让(a/i)继续除以i直到无法整除为止，接着继续遍历i+1，i+2,,,一直遍历到a-1重复上述过程，这样就能得到分解质因数的结果了。但是对于a!也是应用上述试除法进行分解质因数吗？不用这么麻烦的，这里有个很好用的性质：假设a!=p1^α1 * p2^α2 *... pi^αi * ... *pn^αn，则这里的

αi= ⌊a/pi⌋+⌊a/pi^2⌋+⌊a/pi^3⌋+...+⌊a/pi^k⌋（直到⌊a/pi^k⌋=0，这里的⌊⌋ 表示向下取整）

为什么存在上述性质？

因为a!=a * (a-1) * (a-2) * ... * (k * pi) * ... * (2 * pi) * ... * pi * ... *1，又因为最后a!分解质因数后的结果为

a!=p1^α1 * p2^α2 *... pi^αi * ... *pn^αn，所以这里分解质因数后pi的指数αi我们就只要看pi在a!中出现了几次就行了，发现在a * (a-1) * (a-2) * ... * (k * pi) * ... * (2 * pi) * ... * pi * ... *1中pi先是在pi这一项中出现了一次接着又在 (2 * pi)这一项中出现了一次，，，所以在a!中pi总共会出现几次呢？答案是 ⌊a/pi⌋ 次。但是这样就完了吗？当然不是，因为这里的 (k * pi) 这一项中 k可能本身就是pi（没毛病，本来pi * pi也是pi的倍数啊），这样的话pi^2项会对pi的指数贡献两次，之前我们在遍历pi的倍数时已经将pi^2项对pi的指数贡献了一次，所以这里还要继续贡献一次，那么a!中有多少个pi^2项呢？答案是⌊a/pi^2⌋。同理还有pi^3项会对pi的指数贡献3次，pi^4项会对pi的指数贡献4次，，，一直到最后pi^k项（其中⌊a/pi^k⌋=0）

通过上述办法我们的确可以找到这里pi的指数，但是问题是我们还没有办法确定a!中到底哪些质数才是a!的因子pi啊？

没问题，所有的质数都可以通过上述办法来求对应的指数，即使pj作为一个质数但它不是a!的质因子，则我们利用上述αi= ⌊a/pi⌋+⌊a/pi^2⌋+⌊a/pi^3⌋+...+⌊a/pi^k⌋公式计算得到的pj的指数αj也是等于0的，这样就对问题没有影响了。

```Java
public class Main{
    static int N=5010,cnt;//cnt用来记录当前有几个质数
    static int[] primes=new int[N];//用来存储1~N中所有的质数的数组
    static boolean[] st=new boolean[N];
    //st[i]用来表示数i是否是质数（st[i]==true表示i是合数，为什么这样做？
    //因为这里筛选质数的过程是我们首先默认所有的数都是质数然后再去修改因为Java中
    //boolean类型的变量创建时默认值是false，所以我们就将st[i]==false记录为i是质数）
    
    static int[] sum=new int[N];//用来存储分解质因数的过程中各个底数对应的指数，为了后续计算需要
    
    static void getPrimes(int n){//该方法的作用是利用线性筛法得到1~n中所有的质数
        for(int i=2;i<=n;i++){
            if(!st[i]){
                primes[cnt++]=i;
            }
            for(int j=0;primes[j]<=n/i;j++){
                st[primes[j]*i]=true;
                if((i%primes[j])==0){
                    break;
                }

        }
    }
    
    static int get(int n,int p){
        /*
        该方法的作用是得到n!中质数p的指数，为什么要这样做？
        因为后续计算a!=p1^α1 * p2^α2 *... pi^αi * ... *pn^αn的过程中我们是利用循环来实现
        的，针对每一个pi要乘αi次所以我们得将它记录下来
        */
        int res=0;
        while(n!=0){
            res+=n/p;
            n/=p;
        }
        return res;
    }
    
    static List<Integer> mul(List<Integer> list1,int b){//用来计算高精度乘法A*b的结果
        List<Integer> list2=new ArrayList<>();
        int t=0;
        for(int i=0;i<list1.size();i++){
            t+=list1.get(i)*b;
            list2.add(t%10);
```

## 9、容斥原理

### 是什么：

容斥原理是一种组合数学中常用的计数方法，用于解决包含交叠部分的集合的计数问题。该原理的核心思想是通过递归减去交叠部分的计数来得到最终的计数结果。

容斥原理通常用于解决如下类型的问题：给定若干个集合，要求计算它们的并集中元素的个数。这些集合可能有交叠的部分，容斥原理帮助我们避免多次计数相同的元素。

容斥原理的一般表达式如下：

如果有n个集合A1，A2，...，An，那么它们的并集中元素的个数可以表示为：

|A1 ∪ A2 ∪ ... ∪ An| = |A1| + |A2| + ... + |An| - |A1 ∩ A2| - |A1 ∩ A3| - ... - |An-1 ∩ An| + |A1 ∩ A2 ∩ A3| + |A1 ∩ A2 ∩ A4| + ... + (-1)^(n-1) * |A1 ∩ A2 ∩ ... ∩ An|

这个公式的意义在于，首先将所有集合的元素个数相加，然后减去所有两两交叠部分的元素个数，接着加回三个集合交叠部分的元素个数，以此类推，交替加减直到考虑到所有可能的交叠情况。

#### 容斥原理的时间复杂度是多少？

按上述假设有n个集合A1，A2，...，An，则上述加法减法操作总共需要执行多少次？

首先单个集合的加法操作需要执行C(n,1)次，再来两个集合的交集部分需要执行的减法操作为C(n,2)次，再来三个集合的交集部分需要执行的加法操作为C(n,3)次，，，，所以总共的操作执行次数为：C(n,1)+C(n,2)+C(n,3)+...+C(n,n)，用二项式展开该式等于2^n - 1，所以该算法的时间复杂度为：O(2^n)

解题思路：

#### 怎么办：

本题要求求出1~n中能被给定的m个质数中的至少一个整除的数有多少个？这下该如何操作？

##### 解法一：暴力法

遍历1~n中的每个数，对于每个数再进行一次遍历看看它能否被这m个质数中的至少一个整除；这种算法的时间复杂度为：O(n * m)，这里的n是10^9，这里的m是16，所以这里的时间复杂度的数量级为10^10总共需要进行这么多次操作，太麻烦了

##### 解法二：容斥原理

###### 如何将本题与容斥原理构建起来联系呢？

这里当给定一个质数pi的时候，我们可以找到该数对应的一个集合，该集合中的元素就是1~n中能被pi整除的数，这个是可以做到的，只要我们用线性筛法就可以简单的做到，这样就可以找到每个集合中具体的元素是什么了，然后分别求出这m个质数对应的m个集合中的所有具体元素然后再去统计这些元素有多少个（去除重复的）。

###### 但是想一下需要这么麻烦吗？我们需要知道每个集合中的具体元素的吗？

其实不需要，因为最后我们需要的是一个数量而不是具体元素是多少。

###### 那么我们有办法直接求出每个集合中有多少个元素吗？

可以，当给定质数pi的时候，那么该质数对应的集合中存储的就是1~n中能被pi整除的数，这样的数有 ⌊n/pi⌋ 个（这里是向下取整），当给定质数pi，pj的时候，那么会对应两个集合其中一个存储的是1~n中能被pi整除的数另一个集合中存储的是1~n中能被pj整除的数，很明显这两个集合会产生交集，交集对应的元素就是1~n中既能被pi整除又能被pj整除的数，这些数在计数的时候只能算作一次，但是这里被计算了两次，所以我们还得减去这两个集合的交集对应的元素，那么这两个集合的交集元素有多少呢？该交集元素对应的是1~n中既能被pi整除又能被pj整除的数，这样的数总共有 ⌊n/(pi * pj)⌋ 个，为什么？因为这里的pi，pj都是质数，所以既能被pi整除又能被pj整除的数是它们二者的公倍数。同理对于pi,pj,pk三个质数产生的交集的元素个数是 ⌊n/(pi * pj * pk)⌋ 。

###### 如何求出每个集合的元素数前面的符号到底是加去还是减去呢？

经由前面容斥原理的公式：

|A1 ∪ A2 ∪ ... ∪ An| = |A1| + |A2| + ... + |An| - |A1 ∩ A2| - |A1 ∩ A3| - ... - |An-1 ∩ An| + |A1 ∩ A2 ∩ A3| + |A1 ∩ A2 ∩ A4| + ... + (-1)^(n-1) * |A1 ∩ A2 ∩ ... ∩ An|  																							 我们知道对于单个集合中的元素数应该加上，对于两个集合的交集的元素数应该减去，对于三个集合的交集的元素数应该加上，，，所以对于元素数前面的符号到底是加去还是减去取决于该集合中的元素是几个集合相交产生的，那么我们该如何判断该集合中的元素是由几个集合相交产生的呢？很难判断（这里可能的做法就是遍历该集合中的元素看看该元素能被几个质数pi整除就代表该集合中的元素是由几个集合相交产生的）。所以我们换种思路，**这里总共有m个质数对应m个集合，每次从这些集合中取出若干个让它们相交（若是仅仅取出一个集合则代表就是该集合本身），总共对应2^m-1种取法，每一种取法都对应将这m个集合中的若干个进行组合的情况，所以得想办法给这2^m-1种组合情况每一种都给它标记状态表示它是由哪几个集合进行组合形成的，我们发现1~2^m-1这些数的m位二进制表示刚好可以起到这个标记状态的作用，举例：这里假设总共有6个集合，则对于5这个数的6位二级制表示为（000101），这里的二进制表示中总共有6位刚好对应6个集合，然后该二进制数的第1位和第3位为1其余位置为0刚好可以表示选取第1个集合和第3个集合的状态，所以这里1~2^m-1这些数的m位二进制刚好可以与这2^m-1种组合情况一一对应**，所以我们只要遍历1~2^m-1这些数就相当于遍历2^m-1中组合情况，然后该组合情况对应的正负号就取决于该数的二进制表示中有几个1。

###### 该算法的时间复杂度是多少？

这里给定m个质数对应m个集合（每个集合的构造时间这里就不计了），这些集合总共对应2^m-1种组合情况，我们要对这2^m-1种组合情况进行加减运算，所以总共的时间复杂度为：O(2^m)，这里的m=16，所以这里的计算数量级为2^16，其中2^32差不多等于10^9，所以2^16差不多等于10^5所以发现相比较暴力法本算法更高效

```Java
import java.util.*;
public class Main{
    static int M=20;
    static int[] p=new int[M];//记录输入的m个质数
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        int m=sc.nextInt();
        for(int i=0;i<m;i++){
            p[i]=sc.nextInt();//将m个质数存入数组中
        }
        
        int res=0;//用来记录最后的结果
        for(int i=1;i<1<<m;i++){
            /*
            这里不是遍历1~n而是遍历m个集合的组合情况（m个集合总共有2^m-1种组合情况）
            因为1~2^m-1这些数的m位二进制表示刚好与这2^m-1种组合情况一一对应
            */
            
            long t=1;//用来记录pi*pj的结果
            
            int cnt=0;
            //用来记录当前遍历到的组合情况是由几个集合相交产生的
            //（也就是该数的二进制表示中有几个1）
            
            for(int j=0;j<m;j++){
                if((i>>j&1)==1){
                    cnt++;
                    t*=p[j];
                    if(t>n){//注意这里pi*pj的结果可能比n大
                        t=-1;
                        break;
                    }
                }
            }
            if(t!=-1){
                if(cnt%2==1){
                    //根据容斥原理，如果是奇数个集合相交的元素应该加上，
                    //如果是偶数个集合相交的元素应该减去
                    res+=n/t;
                }else{
                    res-=n/t;
                }
            }
        }
        System.out.println(res);
    }
}
```
