# 第六章贪心

## 是什么：

贪心算法（Greedy Algorithm）是一种通过**不断选择当前情况下最优选择**，最终希望得到全局最优解的算法思想。

简单来说：

> 每一步只考虑眼前利益，选择当前看起来最好的方案，不回头修改。

例如：假设现在你要从北京去上海，要求找到最快的交通方式。

有两种策略：

策略1：穷举

考虑：

- 坐飞机？
- 坐高铁？
- 开车？

尝试所有方案，总能找到最快的一种。

策略2：贪心

每一步选择当前最优：

1. 第一步：
   选择最快的交通方式（比如当前位置离高铁站最近，所以选择坐高铁）

2. 第二步：
   选择最快的路线（选择去高铁站最近的路线）

3. 第三步：
   选择最方便的换乘

这种方法速度很快。

但是：

> 每一步最优，不一定导致最终最优。

比如当执行第一步的时候，确实当前位置离高铁站最近离飞机场远，但是等飞机起飞后它的速度远大于高铁可以抹平前面的差距。

所以：**贪心算法不是万能的，必须证明它正确。**



## 为什么：

### （1）为什么贪心可以得到最优解？

并不是所有问题都可以使用贪心算法得到最优解，一个问题能够使用贪心得到最优解通常需要满足两个条件：

#### 1.1贪心选择性质

简单理解：当前选择虽然只看眼前，但是不会影响最终答案。

换句话说：

**第一步大胆选择当前最优，不需要考虑以后反悔。**

例子：区间选点问题

现在有很多会议时间：

```
会议1：
9:00 -------- 10:00

会议2：
9:30 -------- 11:00

会议3：
10:00 ------- 12:00
```

要求：

> 选择尽可能少的时间点，使得覆盖所有的会议时间区间。

假设按照结束时间排序：

```
会议1：
9:00 -------- 10:00

会议2：
9:30 -------- 11:00

会议3：
10:00 ------- 12:00
```

最早结束的是会议1。

贪心选择：

```
10:00
```

为什么？

因为：

```
9:00 -------- 10:00
             ↑
          选择这里
```

如果最优方案选择：

```
9:30
```

那么：

```
9:00 ----9:30----10:00
          ↑
```

其实也能覆盖会议1。

但是：10:00 比 9:30 更靠右，更靠右意味着：后面的会议更容易被覆盖。

所以：把

```
9:30
```

替换成：

```
10:00
```

不会让答案变差。

因此：

> 存在一个最优方案，也选择10:00。

这说明：第一次贪心选择是安全的。



#### 1.2最优子结构

简单理解：一个大问题的最优解，包含剩余小问题的最优解。

继续看区间选点：

第一次：

选择：

```
10:00
```

覆盖：

```
会议1
会议2
```

那么：这些会议可以删除。

剩余：

```
会议3：
10:00 -------12:00
```

问题变成：

```
剩余会议最少需要几个点？
```

这和原问题完全一样。

所以：可以重复使用同样的方法。



## 怎么办：

### （1）如何使用贪心算法？

#### 1.1确定贪心策略

先回答：

> 每一步应该选择什么？

常见策略：

| 问题       | 选择                 |
| ---------- | -------------------- |
| 区间选点   | 最早结束区间的右端点 |
| 活动安排   | 结束时间最早的活动   |
| 霍夫曼编码 | 频率最低的字符合并   |
| 最小生成树 | 权值最小边           |
| Dijkstra   | 距离当前点最近节点   |



#### 1.2排序

很多贪心问题需要排序。

例如：区间选点问题按照结束时间排序：

```
会议A:
9:00----10:00

会议B:
9:30----11:00

会议C:
10:00---12:00
```

排序依据：

```
结束时间从小到大
```

原因：

结束越早，留下更多空间给后面的区间。



#### 1.3遍历选择

伪代码：

```Java
answer = []
for 每一个区间:
    if 当前区间已经被覆盖:
          跳过
    else:
          选择当前区间右端点
          加入answer
```



#### 1.4贪心正确性如何证明？

不要证明：

> 某一种情况有效。

应该证明：

> 贪心选择不会破坏最优解。

常见方法：

1. ==交换论证（最常用）==

   思想：

   ==假设存在一个最优解，如果它和贪心选择不同就把它修改成贪心选择，如果修改后仍然最优说明贪心正确==。

   还是以上述的会议时间选择为例：假设现在存在一个最优方案选择的点是

   ```
   选择9:30
   ```

   贪心选择的点是：

   ```
   选择10:00
   ```

   将最优选择替换成贪心选择：

   ```
   9:30 → 10:00
   ```

   结果覆盖能力不下降，所以贪心选择也是最优。

2. 反证法

   假设贪心答案不是最优，存在更好的答案。然后证明这个更好的答案一定会产生矛盾。

3. 数学归纳法

   证明：

   第一次选择正确；

   假设前k次选择正确；

   证明第k+1次仍正确。



## notes：贪心算法使用注意事项

1. 不是所有问题都适用贪心算法找最优解
2. 要使用贪心算法求最优解必须证明其正确性



## 1、区间问题

## notes：关于区间问题的整理

### 是什么：

区间问题大体可以分为两类：

- 区间选点问题：从所有区间中选择部分区间或者部分区间上的点，==涉及到的是部分区间组成一组==
- 区间分组问题：给所有区间进行分组，==涉及到的是所有区间组成多组==

对区间问题的处理逻辑也是类似，先对区间进行排序，接着遍历所有区间进行对应处理。只是对于不同的情况会对区间按照不同的逻辑进行排序，比如对于区间选点问题是按照区间右端点从小到大排序，对于区间分组问题是按照区间左端点从小到大排序。

### 为什么：

#### （1）为什么区间问题的排序逻辑如此？

为了证明排序逻辑的用处，我们现在假设有一个特别大的区间（左端点特别小，右端点特别大），接着看它在不同场景下的排序处境。

为什么要假设这样一个区间呢？因为只有这样的区间才能满足按照左端点从小到大排序的时候它排在前列，按照右端点从小到大排序的时候它排在后列，也就是说只有这样一个区间才能体现出对于同一个区间在不同排序逻辑下它的处境不同，如果是区间的左端点和右端点都特别大的话那么无论是按照左端点排序还是右端点排序它都排在后列这根本体现不出不同排序规则的作用。

- 区间选点问题：从所有区间中选择部分区间或者部分区间上的点，==涉及到的是部分区间组成一组，按照区间右端点从小到大排序==，因为这里的每个区间都存在可取可不取两种情况，对于那个超大的区间也是如此，为了降低超大区间对别的区间的影响我们可以按照右端点从小到大排序，这样将超大区间放到后列优先处理其他区间
- 区间分组问题：给所有区间进行分组，==涉及到的是所有区间组成多组，按照区间左端点从小到大排序==，因为这里的每个区间都必须取，对于那个超大的区间也是如此，为了降低超大区间对别的区间的影响我们可以按照左端点从小到大排序，这样将超大区间放到前列优先用一个组处理超大区间。我知道这里不太好理解，但是我们可以将每个区间理解成一个个会议，区间端点就是会议开始和结束时间，区间分组就是给会议找教室，要求每个会议必须安排教室并且要求同一个教室不能同时举办两个会议，问最少需要多少个教室能满足要求？这里对于那个超长的会议因为必须要处理所以选择优先处理它，从而避免它对其他会议造成干扰。

==示例1：区间选点问题==

从给定的若干闭区间中，选择尽可能多的区间，使选出的任意两个区间都不相交。这是个典型的区间选点问题，要求从所有区间中选择部分区间组成一组要求它们互不相交。

区间情况如下：

```
[1, 100]
[2, 3]
[4, 5]
[6, 7]
```

贪心策略：

先按照区间右端点从小到大排序，接着遍历所有区间每次选择当前能够选择的、结束最早的区间。

原因是：当前区间结束得越早，留给后续区间的空间越大。

例如：

```
[1,100]
[2,3]
```

虽然 `[1,100]` 开始得更早，但它占用的范围很长会对后续区间的选择产生很大影响，选择 `[2,3]` 对后面的限制更小。



==示例2：区间分组问题==

将所有区间分成若干组，使得同一组中的任意两个区间都不相交，并且组数尽可能少。这里不能舍弃任何区间。这是个典型的区间分组问题，要求对所有区间分组并且满足同一组内的区间互不相交。

可以理解为：

- 每个组是一间教室；
- 每个区间是一场会议；
- 所有会议都必须安排；
- 同一间教室不能同时进行两场会议；
- 求最少需要多少间教室。

贪心策略：

先按照区间左端点从小到大排序，接着遍历所有区间在处理当前区间 `[l,r]` 时，需要检查：已经存在的分组中，是否有某个组已经在 `l` 之前结束。原因是：区间分组本质上是在按照开始时间依次安排所有区间。



### （905）区间选点

![1706086627413](%E7%AC%AC%E5%85%AD%E7%AB%A0%E8%B4%AA%E5%BF%83.assets/1706086627413.png)

解题思路：

本题是要在数轴上选择尽量少的点使得它可以覆盖所有的区间，这里我们先以两个区间为例，如果两个区间相交那么只要在相交部分取一点就可以覆盖住这两个区间，如果两个区间不相交那么为了覆盖住这两个区间至少得取两点，对于多个区间的情况也是同理。

这里其实就是区间选点问题的一种，从部分区间中选择一点组成一组，为什么是部分区间不是所有区间呢？因为如果两个区间相交的话在前一个区间中选择了相交部分的一点则后一个区间就不用取了。

所以我们可以采取下述步骤求解：

1. 先将各个区间按照右端点从小到大排列
2. 接着取第一个区间的右端点看它与第二个区间是否相交，如果相交的话则接着看该点与第三个区间是否相交往后以此类推，如果不相交的话则接着取第二个区间的右端点看它与第三个区间是否相交往后以此类推

看完上述求解步骤有几个问题分别如下？

1. 为什么按照区间右端点从小到大排序？
2. 为什么选点的时候选择区间的右端点？

首先第一个问题，具体解释见上述notes部分。

接着第二个问题，因为这里我们的思路是首先给区间排序，接着遍历所有的区间在当前区间上选择一点看是否与后续区间相交，如果相交的话则接着看该点是否与再后续的区间相交，如果不相交的话则在后续区间上再选择一点看是否与再后续的区间相交。所以为了使得选择的点尽可能覆盖更多的区间自然应该取最右边的点，这就是本题贪心思想的体现。并且可以看到区间的右端点是我们要重点比较的内容所以要按照区间右端点从小到大排序。

示意图如下：

![1706086606994](%E7%AC%AC%E5%85%AD%E7%AB%A0%E8%B4%AA%E5%BF%83.assets/1706086606994.png)

大体思想和示意图都明白了，但是如何证明当前这种思想求得的解就是最有解呢？

==贪心证明==

1. 错误证明

   设 ans 为最优解， cnt为某一个答案。
   欲证：ans = cnt

   ① ans <= cnt， 显然；
   ② ans >= cnt， 这里应该是容易产生困惑的地方。

   首先要清楚一点，ans是一个定值、常数，表示最优解的值； 而cnt它是一个变量，代表某一种方案的值。

   要证: ans >= cnt， 只需要证：ans >= max(cnt)即可，因为如果连最大的cnt都不超过ans，那么所有的cnt都小于等于ans。

   何时取到max？当全部区间两两不相交时，cnt必然取到最大值。（但是，有部分区间相交时，也可以取到最大值，设想一下只有2个区间，中间相交了一小部分，我们可以分别取第一个区间的最左，和第二个区间的最右。但这并不重要，只要我们能证明，在其中一种取到最大值的方案中，ans >= cnt，那么剩下的全部方案的cnt必然小于等于ans。）

   显然，当全部区间两两不相交时，ans = cnt。

   因此由ans >= max(cnt) >= cnt， 可证②也是成立的。

   综上所述，由①②可知，ans = cnt。

为什么上述证明是错误的？

因为上述证明成立的一个前提是ans是一个定值而cnt是一个变量，但实际上ans和cnt都是随着区间情况而变化的变量，详细解释如下：

他的思路是要证 ans >= cnt， 只需要证：ans >= max(cnt)，那么什么时候cnt取得最大值呢？按照贪心算法的思路当区间两两不相交的时候此时需要取的点数是最多的也就是区间个数，此时最优解为了覆盖住所有区间也得保证ans>=区间个数，所以他接着就推导出ans >= max(cnt)，但是也说了ans本身是会随着区间情况而变化的，上述情况只是证明了在区间两两不相交的情况下ans>=cnt，并不能证明存在区间相交的情况下ans>=cnt依然成立。



2. 正确证明

   交换论证（Exchange Argument）

   假设：区间按照右端点排序

   ```
   r1≤r2≤...≤rn
   ```

   第一个区间：

   ```
   I1=[l1,r1]
   ```

   贪心选择的点为区间右端点：

   ```
   p=r1
   ```

   现在要证明：存在一个最优解也包含这个区间右端点。为了证明这个结论，我们可以==先假设存在一个最优解但是它不包含该区间右端点，接着将该最优解中的点换成区间右端点但是该最优解依然成立，这就证明了贪心选择选出的点是最优解==。具体证明如下：

   假设：存在某个最优解`OPT`但是其中不含有`r1`这个点。

   因为第一个区间`[l1,r1]`必须被最优解中的某个点覆盖，假设这个点就是`q`，那么：`l1≤q≤r1`成立。

   接下来就要证将`q`换成`r1`最优解依然成立，如何证明将`q`换成`r1`最优解依然成立呢？

   其实就是要保证原先`q`点所覆盖的区间现在换成`r1`点依然可以覆盖，如何证明原先`q`点覆盖的区间现在换成`r1`点依然可以覆盖呢？

   那就得先找到原先`q`点覆盖的区间，`q`点可以覆盖的区间满足： ` 左端点<=q且右端点>=r1 `，为什么是r1呢？因为所有的区间已经按照右端点从小到大排序了，而区间`I1`是第一个区间所以后续区间的右端点都得大于`r1`，对于满足上述条件的区间无论是`q`点还是`r1`点都可以覆盖住区间范围，所以将`q`点换成`r1`点最优解依然成立。

   综上：贪心选择第一个点不会破坏最优性，接着删除所有被` r1 ` 覆盖的区间，剩余问题还是同样的问题，递归进行。

   最终贪心得到的点数 = 最优点数。

```java
import java.util.*;

class Range implements Comparable<Range>{
    int l,r;
    public Range(int l,int r){
        this.l=l;
        this.r=r;
    }
    
    @Override
    public int compareTo(Range o){
        return Integer.compare(r, o.r);
    }
}

public class Main{
    static int N=100010;
    static int INF=0x3f3f3f3f;//用于表示一个极大的数
    static Range[] ranges=new Range[N];
    
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        for(int i=0;i<n;i++){
            int a=sc.nextInt();
            int b=sc.nextInt();
            ranges[i]=new Range(a,b);
        }
        Arrays.sort(ranges,0,n);
        
        int ans=0;//用于表示最终选取的点数
        int ed=-INF;//用于表示上一个区间的右端点
        for(int i=0;i<n;i++){
            if(ed<ranges[i].l){
                ed=ranges[i].r;
                ans++;
            }
        }
        System.out.println(ans);
    }
}
```





### （908）最大不相交区间数量

![1706087454241](%E7%AC%AC%E5%85%AD%E7%AB%A0%E8%B4%AA%E5%BF%83.assets/1706087454241.png)

解题思路：

本题的意思是给定N个闭区间，然后让你在其中选择若干个区间组成一组，要求满足组内的所有区间互不相交，问这样符合要求的区间最多有多少个。

这是典型的区间选点问题，从所有区间中选择部分区间组成一组，所以按照区间右端点从小到大排序。

所以本题求解步骤如下：

1. 将所有区间按照右端点从小到大排序
2. 遍历所有区间，看当前区间能否加入到现有的组中，如果不能则遍历下一个区间，如果能则将当前区间加入现有的组

看完上述求解步骤有几个问题分别如下？

1. 为什么按照区间右端点从小到大排序？
2. 如何维护现有的组？
3. 如何判断当前区间能否加入到现有的组中？

首先第一个问题，因为这里我们的思路是首先给区间排序，接着遍历所有的区间看当前区间能否加入现有的组，这里能否加入现有的组就是判断当前区间的左端点是否与组的右边界相交，可以看到这里组的右边界是重要的比较目标也是我们重点维护的内容，所以要按照区间右端点从小到大排序。

接着第二个问题，这里我们思考一个问题：我们有必要维护一个完整的组吗？其实没有必要，我们要比较的内容仅仅是组的右边界，所以我们只要用一个整数记录现有组的右边界即可。

最后第三个问题，前面第一个问题也提到了判断当前区间能否加入现有的组中就是看当前区间的左端点是否与组的右边界相交。

```java
import java.util.*;

class Range implements Comparable<Range>{
    int l,r;
    public Range(int l,int r){
        this.l=l;
        this.r=r;
    }
    
    @Override
    public int compareTo(Range o){
        return Integer.compare(r, o.r);
    }
}

public class Main{
    static int N=100010;
    static int INF=0x3f3f3f3f;//用于表示一个极大的数
    static Range[] ranges=new Range[N];
    
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        for(int i=0;i<n;i++){
            int a=sc.nextInt();
            int b=sc.nextInt();
            ranges[i]=new Range(a,b);
        }
        Arrays.sort(ranges,0,n);
        
        int ans=0;//用于表示最终选取的点数
        int ed=-INF;//用于表示上一个区间的右端点
        for(int i=0;i<n;i++){
            if(ed<ranges[i].l){
                ed=ranges[i].r;
                ans++;
            }
        }
        System.out.println(ans);
    }
}
```

### （906）区间分组

![image-20260717103521850](./%E7%AC%AC%E5%85%AD%E7%AB%A0%E8%B4%AA%E5%BF%83.assets/image-20260717103521850.png)

解题思路：

本题是要在给定的N个区间上进行分组使得每个组中的区间互不相交，并且使得分组数尽可能小。

本题属于典型的区间分组问题，将所有区间分成多组，所以得按照区间左端点从小到大排序。

所以我们可以采取下述步骤求解：

1. 将所有区间按照左端点从小到大排列
2. 遍历每个区间，看其能否放到现有的组中
   - 如果不能，则重新创建一个新的组并将当前区间加入该组中
   - 如果能，则将当前区间加入当前组中
3. 最后统计有多少个组

这里有几个问题？

1. 为什么要按照区间左端点从小到大排列，明明前面的题目都是按照区间右端点从小到大排列？
2. 用什么数据结构来维护现有的组？
3. 如何判断当前区间能否加入某个组中？
4. 如果有多个组满足条件则当前区间应该放到哪个组中？

首先第一个问题，具体解释看上述notes部分。

第二个问题，这里我们思考一个问题：为什么要维护现有的组？因为后续我们得遍历所有区间看当前区间能否加入到现有的组中，所以我们真的是要维护组中的所有元素吗？其实不是，我们要维护的仅仅是组的右边界即可（组的右边界即组中所有区间的右边界的最大值）。这里我们采用小根堆来维护现有的组，堆中每个节点都代表一个组，节点的值就是所在组的右边界，根节点就是所有组中右边界最小的值。

第三个问题，前面第一个问题中已经提到了，如何判断当前区间能否加入某个组中就是判断当前区间的左端点是否与组的右端点相交。

第四个问题，如果有多个组都不和当前区间相交的话那么理论上随便将当前区间放入哪个组都行，但是真的是这样吗？

证明一下，我们要证明的就是无论将当前区间放入哪个组中都不会影响最终的组数。

假设现在有两个组`X1=[l1,r1]和X2=[l2,r2]（其中l1,r1分别代表X1组的左右边界，l2,r2也是同理）`都不和`当前区间[l3,r3]`相交即`l3>r1且l3>r2`，无论将当前区间加入哪个组中都会重新更新该组的右边界为当前区间的右端点，另一个组的右边界则不变，遍历`后续区间[l4,r4]`的时候因为区间已经按照左端点从小到大排列了，所以后续区间的左端点一定大于当前区间的左端点即`l4>l3`，又因为`l3>r1且l3>r2`，所以`l4>r1且l4>r2`即后续区间一定不会和当前这两个未经过更新的组相交，假如将当前区间放入组X1中则X1的范围变成`[l1,r3]`，那么后续区间与两个组的相交情况就变成了：后续区间与X2组不相交，后续区间与X1组的相交情况要判断l4>r3是否成立。同理将当前区间放入组X2中情况不变，所以无论将当前区间放入哪个组中都不会影响最终的组数。

但是这里我们就选择根节点所在的组然后将当前区间放进去，这也是贪心思想的体现。

```java
import java.util.*;

class Range implements Comparable<Range>{
    int l,r;
    public Range(int l,int r){
        this.l=l;
        this.r=r;
    }
    
    @Override
    public int compareTo(Range o){
        return Integer.compare(this.l, o.l);
    }
}

public class Main{
    static int N=100010;
    static Range[] ranges=new Range[N];
    public static void main(String[] args){
        Scanner sc=new Scanner(System.in);
        int n=sc.nextInt();
        for(int i=0;i<n;i++){
            int a=sc.nextInt();
            int b=sc.nextInt();
            ranges[i]=new Range(a,b);
        }
        Arrays.sort(ranges,0,n);
        
        Queue<Integer> minheap = new PriorityQueue<>(); // 小根堆
        for(int i=0;i<n;i++){
            //如果小根堆中没有元素或者小根堆的根节点与当前区间相交则重新创建一个新的组并将当前区间加入到该组中
            if(minheap.size()==0 || minheap.peek()>=ranges[i].l){
                minheap.add(ranges[i].r);
            }else{//如果小根堆的根节点与当前区间不相交则将当前区间加入根节点所代表的区间并重新维护该区间的右边界
                minheap.poll();
                minheap.add(ranges[i].r);
            }
        }
        System.out.println(minheap.size());
    }
}
```
